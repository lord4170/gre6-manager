# gre6ctl 2.1 — مدیریت حرفه‌ای GRE over IPv6

یک ابزار مستقل برای اتصال **یک سرور خارج به چند سرور ایران** با IPv4 خصوصی نقطه‌به‌نقطه روی GRE6؛ بدون NAT، بدون IP forwarding و **بدون تغییر default route**. این پروژه از صفر نوشته شده و وابستگی کد به `ipv6-gre-manager` ندارد. از مخزن مرجع برای بررسی قابلیت‌ها و الگوی معماری استفاده شده است.

## معماری و تخصیص IP

```
                      IPv6 Public Network
                              |
                     Foreign / HUB Server
                     2001:...:FOREIGN
                       |             |
                     iran1         iran2          ... iranN
                     GRE6          GRE6
                10.250.0.1/30   10.200.0.1/30
                       |             |
                    Iran #1       Iran #2
                10.250.0.2/30   10.200.0.2/30
```

تخصیص خودکار از پنج محدوده خصوصی مستقل `/16` به ترتیب `10.250.0.0/16`، `10.200.0.0/16`، `10.150.0.0/16`، `10.100.0.0/16` و `10.50.0.0/16` استفاده می‌کند. در دور اول از هر محدوده آدرس‌های `.1` و `.2` و در دور دوم `.5` و `.6` انتخاب می‌شود؛ هر تونل subnet مستقل `/30` دارد. اگر بلوک پیشنهادی در شبکه یا تونل موجود اشغال باشد، allocator اولین subnet آزاد بعدی را در همین ترتیب انتخاب می‌کند. فایل‌های پیکربندی و `flock` ثبت و کنترل تداخل را در حین ذخیره اتمیک می‌کنند.

**مهم:** برای تخصیص بدون تداخل بین چند سرور، **همه تونل‌ها را ابتدا روی سرور مرکزی خارج بسازید** و خروجی `export-peer` هر تونل را به سرور ایران متناظر وارد کنید. هیچ سیستمی بدون هماهنگی مرکزی نمی‌تواند تداخل IP بین ماشین‌های مستقل را با قطعیت کشف کند. اسکریپت تداخل را با تمام تانل‌های ثبت‌شده روی ماشین و شبکه‌ها و routeهای IPv4 همان ماشین می‌سنجد؛ از وضعیت سایر سرورها به‌صورت خودکار خبر ندارد.

### پیش‌نیازها

- Debian 11/12/13 یا Ubuntu 20.04/22.04/24.04 (معماری مبتنی بر Linux و systemd؛ روی همه نسخه‌ها به صورت عملی آزمایش نشده)
- `python3` (فقط کتابخانه استاندارد)، `iproute2`، `iputils-ping` (برای عیب‌یابی) و `systemd`
- دسترسی root، پشتیبانی کرنل از `ip6_gre` و IPv6 قابل‌مسیر‌یابی بین دو سرور
- باز بودن **IPv6 Next Header / IP protocol 47 (GRE)** در هر دو سمت و فایروال ارائه‌دهنده؛ **پورت TCP/UDP 47 نیست**.

برای نصب بسته‌ها در Debian/Ubuntu:

```bash
sudo apt update
sudo apt install -y python3 iproute2 iputils-ping
```

پس از کپی پوشه پروژه روی **هر سرور**:

```bash
cd gre6-manager
sudo bash install.sh
sudo gre6ctl menu
```

یا بدون نصب از همان پوشه: `sudo python3 ./gre6ctl --help`. برای استفاده از systemd، نصب لازم است. فایل‌های نصب‌شده:

- `/usr/local/sbin/gre6ctl`
- `/etc/gre6ctl/tunnels/*.json` (دسترسی فقط root)
- `/etc/systemd/system/gre6ctl@.service`

## سناریوی ۱ خارج و ۳ ایران

در دستورها `FOREIGN_IPV6` و `IRAN_X_IPV6` را با IPv6 عمومی واقعی تعویض کنید. این دستورها روی **سرور خارج** اجرا می‌شوند:

```bash
sudo gre6ctl create iran1 --local6 FOREIGN_IPV6 --peer6 IRAN_1_IPV6 --enable
sudo gre6ctl create iran2 --local6 FOREIGN_IPV6 --peer6 IRAN_2_IPV6 --enable
sudo gre6ctl create iran3 --local6 FOREIGN_IPV6 --peer6 IRAN_3_IPV6 --enable
sudo gre6ctl ipam
```

IPهای پیشنهادی با فرض آزاد بودن محدوده‌ها:

| تونل | subnet | IPv4 سرور خارج | IPv4 سرور ایران |
|---|---|---|---|
| iran1 | `10.250.0.0/30` | `10.250.0.1` | `10.250.0.2` |
| iran2 | `10.200.0.0/30` | `10.200.0.1` | `10.200.0.2` |
| iran3 | `10.150.0.0/30` | `10.150.0.1` | `10.150.0.2` |
| iran4 | `10.100.0.0/30` | `10.100.0.1` | `10.100.0.2` |
| iran5 | `10.50.0.0/30` | `10.50.0.1` | `10.50.0.2` |
| iran6 | `10.250.0.4/30` | `10.250.0.5` | `10.250.0.6` |

### تأیید IP پیشنهادی هنگام ایجاد تونل

در منوی `sudo gre6ctl menu` (گزینه **2**) و همچنین در دستور `sudo gre6ctl create ...` که IP دستی تعیین نشده، ابتدا subnet و دو IPv4 پیشنهادی نمایش داده می‌شود:

```text
Suggested private IPv4s for iran2:
  THIS / foreign server: 10.200.0.1
  PEER / Iran server:    10.200.0.2
  Private subnet:        10.200.0.0/30
Use these IPs? (Y/n):
```

- با **Enter یا Y**، IPهای پیشنهادی تأیید می‌شوند.
- با **N**، انتخاب بین `pair` (ورود دو IP دلخواه) یا `subnet` (ورود شبکه خصوصی `/30` دلخواه) نمایش داده می‌شود.
- IPهای دستی باید دو IP قابل استفاده از یک subnet خصوصی `/30` باشند؛ ترتیب آن‌ها را می‌توان برعکس کرد. انتخاب دستی همچنان از لحاظ تداخل اعتبارسنجی می‌شود.
- اگر دستور از یک اسکریپت غیرتعاملی اجرا می‌شود، افزودن `--accept-auto` به `create` صراحتاً اجازه استفاده از اولین subnet آزاد را بدون پرسش می‌دهد. **بدون این گزینه، اگر ورودی تعاملی وجود نداشته باشد، عملیات با خطا متوقف می‌شود و تانلی ساخته نمی‌شود.**
- اگر هنگام اجرای پرسش، پردازش دیگری subnet پیشنهادی را اشغال کند، عملیات با خطای تداخل متوقف می‌شود؛ IP دیگری بدون تأیید شما انتخاب نمی‌شود. کافی است دستور را دوباره اجرا کنید.
- در دستور `create` اگر `--subnet` یا هر دو `--local-ip` و `--peer-ip` را وارد کنید، این یک انتخاب صریح است و پرسش تأیید پیشنهاد خودکار اجرا نمی‌شود.

مثال اجرای بدون تعامل:

```bash
sudo gre6ctl create iran1 --local6 FOREIGN_IPV6 --peer6 IRAN_1_IPV6 --accept-auto --enable
```

**ایجاد سمت مقابل:**

روی سرور خارج برای `iran1`:

```bash
sudo gre6ctl export-peer iran1
```

خروجی یک رشته با پیشوند `gre6ctl1:` است. روی ایران شماره ۱:

```bash
sudo gre6ctl import-peer 'gre6ctl1:PASTE_THE_FULL_TOKEN_HERE' --enable
sudo gre6ctl doctor iran1
```

همین کار را برای `iran2` روی ایران شماره ۲ و `iran3` روی ایران شماره ۳ تکرار کنید. `export-peer` به‌طور خودکار IPv6های محلی/مقابل و IPv4های دو سمت را برعکس می‌کند. اتصال روی هر سرور تنها از IPv6های مربوط به همان دو سرور استفاده می‌کند.

> توکن رمزنگاری یا امضا نشده است و فقط JSON در Base64URL است. آن را از کانال مورد اعتماد منتقل کنید و به داده‌های منبع اعتماد کنید. GRE ترافیک را رمزنگاری نمی‌کند.

## IP خصوصی دلخواه

### استفاده از subnet مشخص

```bash
sudo gre6ctl create iran4 \
  --local6 FOREIGN_IPV6 --peer6 IRAN_4_IPV6 \
  --subnet 10.250.50.0/30 --enable
```

در این نمونه IP خارجی `10.250.50.1` و ایران `10.250.50.2` خواهد بود.

### انتخاب آدرس دقیق هر سمت

```bash
sudo gre6ctl create iran5 \
  --local6 FOREIGN_IPV6 --peer6 IRAN_5_IPV6 \
  --local-ip 10.80.4.2 --peer-ip 10.80.4.1 --enable
```

هر دو IP باید **دو میزبان قابل استفاده در یک `/30`** از محدوده RFC1918 باشند (در مثال بالا `10.80.4.0/30`). برای IP دلخواه خارج از محدوده پیش‌فرض، کنترل تداخل همچنان فعال است. اگر subnet فعلاً اشغال باشد، اسکریپت با خطا متوقف می‌شود.

قبل از تخصیص دستی می‌توانید بررسی کنید:

```bash
sudo gre6ctl check-subnet 10.80.4.0/30
```

## تغییر IP یک تونل موجود

ابتدا روی سرور خارج:

```bash
sudo gre6ctl edit iran2 --subnet 10.250.100.0/30
sudo gre6ctl export-peer iran2
```

روی سرور ایران شماره ۲، توکن جدید را با گزینه `--update` وارد کنید:

```bash
sudo gre6ctl import-peer 'gre6ctl1:NEW_TOKEN' --update
```

با تغییر subnet هر دو سمت باید تنظیم شوند؛ تا زمانی که طرف مقابل به‌روزرسانی نشده ارتباط ممکن است قطع باشد. **IP جدید روی یک اینترفیس فعال به‌صورت لحظه‌ای جایگزین می‌شود**؛ اگر اعمال محلی خطا بدهد، تلاش برای بازگردانی تنظیمات قبلی انجام می‌شود.

انتخاب دلخواه هر دو آدرس در تغییر:

```bash
sudo gre6ctl edit iran2 --local-ip 10.80.8.2 --peer-ip 10.80.8.1 --subnet 10.80.8.0/30
```

حتماً توکن سمت مقابل را دوباره صادر و وارد کنید. اگر روی سرور ایران هم جداگانه و بدون هماهنگی IP را تغییر دهید، نرم‌افزار خارجی نمی‌تواند تداخل بین دو سرور را تشخیص دهد.

## مدیریت، عیب‌یابی و بکاپ

```bash
sudo gre6ctl                        # منوی مدیریتی
sudo gre6ctl list                   # خلاصه تونل‌ها
sudo gre6ctl ipam                   # فهرست IPهای تخصیص‌یافته و بلوک بعدی
sudo gre6ctl status iran1           # تنظیمات و وضعیت اینترفیس
sudo gre6ctl doctor iran1           # پیش‌نیاز IPv6 / GRE / ping / تداخل
sudo gre6ctl doctor-all             # بررسی همه تونل‌ها
sudo gre6ctl up iran1               # بالا آوردن بدون تغییر بوت
sudo gre6ctl down iran1             # خاموش کردن موقت
sudo gre6ctl enable iran1           # فعال‌سازی و راه‌اندازی در boot
sudo gre6ctl disable iran1          # غیرفعال در boot و stop
sudo gre6ctl restart iran1          # بازسازی اینترفیس
sudo gre6ctl backup /root/gre6-backup.json
sudo gre6ctl restore /root/gre6-backup.json  # فقط روی مدیر فاقد تونل‌های هم‌نام
sudo gre6ctl delete iran1 --yes     # حذف اینترفیس مالکیتی + config
```

فایل پشتیبان فقط کانفیگ است، نه ترافیک یا وضعیت runtime؛ بازگردانی به‌صورت خودکار تانل‌ها را فعال نمی‌کند. قبل از restore از سیستم پشتیبان بگیرید و بعد هر تانل را `enable` کنید.

### عیب‌یابی پیشنهادی

```bash
sudo gre6ctl doctor iran1
ip -d link show dev iran1
ip -4 addr show dev iran1
ip -6 route get IRAN_IPV6 from FOREIGN_IPV6
ping -6 IRAN_IPV6
ping -4 -I iran1 10.250.0.2
sudo journalctl -u gre6ctl@iran1.service -n 60 --no-pager
```

- اگر IPv6 زیرساخت یا route کار نکند، GRE هم بالا نمی‌آید.
- اگر IPv6 Ping موفق ولی IPv4 Ping داخل تانل ناموفق باشد، **protocol 47 GRE**، فایروال دو سمت، اشتباه بودن IPها یا MTU را بررسی کنید. ICMP در برخی شبکه‌ها مسدود است و به‌تنهایی معیار قطعی نیست.
- MTU پیش‌فرض `1400` است؛ در صورت اختلال بسته‌های بزرگ، دو سمت را روی MTU کوچک‌تر مثل 1280 یا 1200 تنظیم کنید و وضعیت Path MTU را بررسی کنید.
- برای boot سرویس از `network-online.target` استفاده می‌کند و در صورت خطای راه‌اندازی با فاصله ۱۰ ثانیه دوباره تلاش می‌کند.
- برای تست سرعت می‌توانید جداگانه `iperf3` نصب کنید و آن را به IPv4 داخلی تانل bind کنید؛ این ابزار هیچ پورت TCP/UDP را باز نمی‌کند.

## ایمنی و محدودیت‌ها

1. **هیچ IP routing عمومی، NAT، firewall rule یا sysctl forwarding در این ابزار تغییر نمی‌کند.** فقط اینترفیس GRE خودش و route متصل `/30` ایجاد/حذف می‌شود.
2. حذف یا بازسازی فقط روی اینترفیس‌هایی مجاز است که با alias `gre6ctl:NAME` ایجاد شده‌اند؛ اگر اینترفیس هم‌نام غیرمدیریتی وجود داشته باشد، عملیات متوقف می‌شود.
3. آدرس‌های انتخابی باید خصوصی RFC1918 باشند. تخصیص خودکار `/30`، پیش‌نمایش و درخواست تأیید دارد و هنگام ذخیره مجدداً زیر file-lock از نظر تداخل اعتبارسنجی می‌شود.
4. بررسی تداخل محدود به کانفیگ‌های همین مدیریت‌کننده، IPv4های تنظیم‌شده و routeهای قابل‌مشاهده **روی سرور محلی** است. تغییرات روی دیگر ماشین‌ها خودکار خوانده نمی‌شود. برای جلوگیری از تضاد سراسری، فقط از سرور مرکزی خارج IP تخصیص دهید و تنظیمات را export/import کنید.
5. ترافیک GRE **رمزنگاری و احراز هویت ندارد**. برای داده‌های حساس از WireGuard یا IPsec استفاده کنید.
6. اگر ابزار GRE دیگری با همین نام اینترفیس و فایل‌های legacy وجود دارد، قبل از تغییر از کانفیگ‌های آن backup بگیرید. نسخه حاضر به‌صورت خودکار فایل‌های قدیمی `.conf` را به `.json` تبدیل نمی‌کند.
7. تغییر یک سرور به معنی همگام‌سازی خودکار طرف مقابل نیست؛ بعد از هر ویرایش آدرس/MTU/endpoint، خروجی جدید را دستی وارد کنید.

## آزمون

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile gre6ctl
```

آزمون‌های واحد مسیرهای تخصیص IP، تداخل، ساخت توکن، وارد کردن، محافظت از رابط‌های نامرتبط و حذف کانفیگ بدون خطر را می‌سنجند. این تست‌ها **جای آزمایش زنده روی دو سرور واقعی** با فایروال/IPv6 واقعی را نمی‌گیرند.


## نصب تک‌دستوری از GitHub

1. همه فایل‌های این پوشه (از جمله `bootstrap.sh`، `gre6ctl` و `install.sh`) را در ریشه مخزن عمومی GitHub آپلود کنید.
2. در `bootstrap.sh` عبارت `YOUR_USERNAME` را با نام کاربری GitHub خودتان عوض کنید.
3. اگر شاخه اصلی مخزن شما `main` نیست، مقدار `REF` را متناسب با آن تغییر دهید.
4. روی هر سرور دستور زیر را اجرا کنید (به جای USERNAME نام کاربری خودتان):

```bash
curl -fsSL https://raw.githubusercontent.com/USERNAME/gre6-manager/main/bootstrap.sh | sudo bash
```

این دستور فایل‌های `gre6ctl` و `install.sh` را بدون git clone دانلود می‌کند، نصب می‌کند و سپس منو را اجرا می‌کند.
برای اجرای دوباره منو: `sudo gre6ctl menu`

**نکته امنیتی:** این روش کد دریافت‌شده از GitHub را با دسترسی root اجرا می‌کند. قبل از اجرا فایل‌ها را بررسی کنید. برای استقرارهای حساس، به جای `main` از یک تگ ثابت یا commit SHA بررسی‌شده استفاده کنید. این نسخه امضای رمزنگاری‌شده فایل‌ها را بررسی نمی‌کند.
